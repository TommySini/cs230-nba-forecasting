# Expanded cohort and model recommendation

The new collection supports a substantially larger experiment. Preserve old sources and use a new snapshot: provisional research counts are **1,632 TRAIN / 201 DEV / 147 TEST**, with approximately **1,506 / 190 / 140** satisfying the current statistical-history rules. TRAIN spans 2012–13 through 2023–24; DEV is 2024–25; TEST is 2025–26. These are metadata-audited candidates pending source reconstruction, not completed accepted training inputs. See [data audit](data_audit.md) and [provenance review](provenance_review.md).

**First new forecaster candidate: OpenAI gpt-oss-20b. Second candidate if affordable: Gemma 3 27B IT.** Keep the existing Qwen2.5-14B as the historical/control implementation. This is a priority for task-specific qualification, not a claim that either new model is already a better NBA forecaster. [Model audit](model_audit.md)

OpenAI documents a June 1, 2024 knowledge cutoff for [gpt-oss-20b](https://developers.openai.com/api/docs/models/gpt-oss-20b); Google documents an August 2024 training-data cutoff for [Gemma 3](https://ai.google.dev/gemma/docs/core/model_card_3). Both precede the first proposed DEV game, October 23, 2024. This follows BAM's declared-knowledge-cutoff criterion even though the models were released in 2025. Pin exact model/tokenizer revisions and retain the qualification that reported cutoffs do not independently audit every post-training example.

GPT-oss is attractive because it offers accessible weights, reasoning capabilities and an official parameter-efficient training recipe. The [official 20B recipe](https://developers.openai.com/cookbook/articles/gpt-oss/fine-tune-transfomers) uses one H100 80GB but only 2,048-token sequences. Our real report lengths, joint head, generation/repair path and exact-resume machinery still need a bounded compatibility/memory/throughput probe. Gemma provides an independent dense model family for a matched comparison; it likewise needs implementation and cost verification. Larger gpt-oss-120b is an optional capacity comparison only after costing; its single-H100 inference claim does not establish training feasibility.

The previously suggested Qwen3.6 and Gemma 4 are not approved for this season split: Qwen3.6 lacks verified sufficiently early cutoff evidence in the reviewed card; Gemma 4 reports January 2025 pretraining data, after early DEV games. Original Qwen3 models could be considered with the smaller late-2025 DEV alternative or better cutoff evidence. No evaluation dates should be moved merely to manufacture a preferred model's favorable result.

Use a strong modern API teacher for TRAIN-only postmortems/gold, selected by source-grounding performance on the existing manual cases. Teacher choice is separate from the forecaster; no API provider/account is configured or selected yet. Every model that influences DEV/TEST inputs or predictions, including research, semantic review and repair, needs the agreed temporal qualification. A modern TRAIN-only teacher cannot become a hidden modern held-out critic.

Select among at most two new forecaster candidates using the same candidate games, reviewed research, original boosting hyperparameters, training/selection allowance and DEV Brier. Inspect factual interpretation on TRAIN examples first. Keep TEST out of selection, save predictions before scoring, and compare the booster and hybrid on exactly the same games. Prior historical exposure means this is an exploratory backtest; preserve a future prospective benchmark.

The immediate next work is dataset import/reconstruction plus a frozen split and actual token-length sizing. After that, qualify one forecaster and one teacher on a bounded sample before committing to full gold generation and training. The user's **$150 total remaining-work ceiling is unchanged**, and no new spending occurred during this review. The previous ledger's uncommitted allowance was $136.41; the expanded workflow has not been demonstrated to fit it. Historical Qwen throughput must not be presented as measured gpt-oss/Gemma cost.
